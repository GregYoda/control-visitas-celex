Configuración
Valores por defecto de una visita tipo Entrevista

Se prellenan al activar el check "Visita tipo Entrevista" al registrar. Deja un campo vacío (o "No prellenar" en la fecha) para que no se prellene. Siguen siendo editables por quien registra.

Cierre automático de visitas

Cada día, a la hora indicada, el sistema registra la salida de las visitas que quedaron "Dentro" (sin registrar salida) y envía un aviso con el total a los correos indicados. Separa varios correos con punto y coma (;). Deja los correos vacíos para no enviar aviso.

Con los valores por defecto, la foto de la visita con ID 1 se guarda como CV0000000001.jpg.
Usuarios VIP / kiosko / reclutadores: listas de IDs de usuario (el que aparece al iniciar sesión) separados por coma; vacío = nadie.

📌 Notas para el administrador

Recordatorio de cómo funciona el acceso y detalles que rara vez cambian. No editable; solo referencia.

🔑 Inicio de sesión (WishPOS)

  • El login pide solo la contraseña de WishPOS (sin usuario). El sistema no crea usuarios: valida contra WishPOS.
  • El ID de usuario que devuelve el login es el que se usa en las listas de abajo (VIP / kiosko / reclutadores).
  • Tras iniciar sesión se entra directo a Control de Visitas (ya no hay menú intermedio).

👁️ Qué muestra u oculta el sistema según el usuario

  • Tarjetas "Configuración" y "Empleados": solo se ven si el usuario tiene el permiso de WishPOS CV.200.00 (Pantalla de Identidad). Sin ese permiso, no aparecen.
  • Usuarios VIP (lista de IDs): ven el check "⭐ Visita VIP" al registrar; la etiqueta muestra ⭐.
  • Usuarios kiosko (lista de IDs): al iniciar sesión entran directo al kiosko (terminal de caseta); "Salir del kiosko" cierra la sesión.
  • Usuarios reclutadores (lista de IDs): ven el check "Visita tipo Entrevista" al registrar (prellena los valores de abajo).
  • ⏱️ Los cambios en estas listas surten efecto la próxima vez que esa persona inicie sesión.

🔢 Códigos

  • Código de acceso (visitante, 6 dígitos): se genera al registrar; sirve una sola vez y solo el día de la visita.
  • Código de salida (visitante, 6 dígitos): se genera al entrar; válido hasta 48 h después del acceso.
  • Código de asistencia (empleado/mensajero, 6 dígitos): lo genera el sistema (no se captura), personal y permanente.

👥 Empleados y asistencia

  • Los mensajeros solo registran entrada; los empleados marcan salida a comer → regreso → salida (con salida anticipada permitida).
  • Carga masiva desde otro sistema (área de sistemas): insertar en la base con el código en blanco y correr sp_CV_Empleados_GenerarCodigosFaltantes, o dar de alta uno por uno con sp_CV_Empleados_Alta.

📷 Fotos y 📧 correo

  • Las fotos se guardan en RutaFotos\Año\Mes\Tipo (Visita / Entrevista / Asistencia). La cámara requiere HTTPS (excepto en localhost).
  • El correo de confirmación al visitante lo envía un proceso de SQL Server (cola WM_Correo en la base de WishPOS), no la aplicación.

🖨️ Kiosko e impresión de etiqueta

  • La etiqueta imprime directo a la impresora predeterminada, sin diálogo, si Chrome se abre con --kiosk-printing (ver docs/iniciar-kiosko-caseta.bat). Dejar la impresora térmica como predeterminada.
  • Tamaño de etiqueta: 3.5" × 1.5" (blanco y negro).
